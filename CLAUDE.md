# CLAUDE.md

Native macOS AI note-taking app. Pure Swift/SwiftUI — **there is no Rust**; the name is a joke that
stayed. Loaded into every session, so it stays lean.

**The approved spec is `docs/superpowers/specs/2026-07-11-rusty-noter-design.md`** — read it for any
decision this file doesn't cover. Five build phases in §13: 1 vault+editor · 2 Claude skill ·
3 meeting capture · 4 intelligence · 5 MCP server + polish.

## Stack

Swift/SwiftUI, macOS 26+. Xcode 26.4.1. Project generated by **XcodeGen** from `project.yml`
(`brew install xcodegen`). SPM packages:

- `Packages/NoterCore` — vault store, FSEvents watcher, GRDB FTS5 index, `INDEX.md`/`CLAUDE.md`/`AGENTS.md`
  generators, `VaultCoordinator` façade. ~79 tests.
- `Packages/NoterEditor` — markdown highlighter, NSTextView wrapper.
- `App/` — SwiftUI three-pane shell, editor, Cmd+K palette, settings/welcome.

## Non-negotiables

- **Fully local AI. No cloud, no API keys.** WhisperKit for transcription; Apple Foundation Models
  behind a `TextIntelligence` protocol so Ollama can swap in if FM summaries disappoint.
- **Files are truth.** Notes are plain markdown in `~/Notes`. Every index — SQLite FTS5, `INDEX.md` —
  is a rebuildable cache and never the source of truth.
- **Agents are first-class consumers**, not an afterthought: Claude skill, generated `CLAUDE.md`/`AGENTS.md`
  in the vault, MCP server. **No in-app chat** — Claude *is* the chat interface.
- No resident daemons; lifecycle concerns drove the engine choices.

## Do not re-thrash the toolbar

The "seamless toolbar" goal — bar background identical to content, Notes-style separator, consistent
across windowed / sidebar-collapsed / full-screen — **is not achievable through SwiftUI
`NavigationSplitView` on macOS 26.** Confirmed empirically over a long session; every lever traded one
glitch for another (`.toolbarBackground` paints per-column; `.toolbarBackgroundVisibility(.hidden)` and
`fullSizeContentView` let list rows bleed into the titlebar; window-level `backgroundColor` works until
full-screen, where macOS re-hosts the toolbar outside the window entirely).

The visible band is the macOS-26 Liquid Glass scroll-edge effect, not the titlebar separator —
`titlebarSeparatorStyle = .none` does nothing. **Shipped the plain native toolbar.** The only reliable
route to the custom look is a hand-built AppKit shell (`NSWindow` + `NSToolbar` with
`sidebarTrackingSeparator` + `NSSplitViewController`), owning fullscreen explicitly. That is a
deliberate future project, not a SwiftUI tweak.

## Current state

Phase 1 merged to `main` (tag `v0.1.0-phase1`). Branch `ui-refresh` carries the native WYSIWYG editor
(glyph-nulling off the active paragraph via `NSLayoutManagerDelegate.shouldGenerateGlyphs` in our own
NSTextView — stock `TextEditor(AttributedString)` is inline-only and a dead end), the time-grouped note
list (custom ScrollView + LazyVStack, **not** SwiftUI `List` — its system selection can't be suppressed
on macOS 26), delete-to-Trash, and frontmatter-flag pinning.

**Backlog:** salvaged-note read-only banner (surface `NotesStore.unparseablePaths`) · mtime/conflict
detection for the autosave-before-Reload lost-update · App-layer test target · per-vault `index.db`
(currently one shared file, safe via rebuild-on-start) · pin toggle doesn't animate (the `withAnimation`
gate in `AppModel.activate` keys on note-set membership only) · pin/delete on a salvaged note silently
no-ops (`try?` swallows `refusingToRewriteUnparseable`) · note title saves on Return but not click-away.

Accepted by design: one-frame "Select a note" flash on delete; Delete key deletes with no confirm
(Trash → Put Back is the undo).

## Conventions

- Design system: Crafted Minimal (`~/design/design.md`). Native apps may use SF Pro as the theme layer,
  but tokens, the 4px spacing scale, motion (150–180ms micro, no bounce) and the hard rules don't swap.
- Build is verified in CI; **pixel verification needs a manual pass** — the build environment has no
  Screen Recording TCC. Visual acceptance items live in the phase acceptance doc.
- Fold shipped UI decisions back into `~/design/design.md` rather than leaving them local.
